04 · Deactivation reconciliation

A second system that checks the first one

Automation can fail quietly. This read-only control compares deactivated accounts across identity, email, and collaboration systems and reports exactly where the records disagree.

Detective control

Checks

  • Cross-system account-state comparison
  • Itemized discrepancies rather than a pass/fail total
  • Scheduled review outside the lifecycle workflow

Deliberate limitation

  • Read-only by design
  • No automatic remediation
  • Dedicated minimal-permission identity

Why separate it?

The control should still be useful when the automation it checks is wrong. Sharing write behavior would defeat the point.

Okta · Google Workspace · Slack · Read-only reconciliation

08 · Vendor assurance

One source record, several useful views

A reconciliation uncovered that vendor and agreement records were living in too many places. I designed a normalized system that keeps the source record, review status, and downstream compliance views connected.

System design

Problem

  • Vendor data split across separate trackers
  • Agreement status difficult to verify
  • Downstream lists drifting from source records

Model

  • Linked evidence rather than duplicated fields

Use

  • Clear gaps without publishing internal vendor data
  • A system people can maintain without a separate platform

Notion · Vendor inventory · Agreement tracking · Compliance views

Architecture principles

Patterns shared across the systems

Safe defaults

Potentially destructive writes begin disabled or dry-run and require deliberate enablement.

Least privilege

Read-only jobs use read-only service identities rather than inheriting broader administrative scopes.

Human control

Automation handles repeatable work while preserving review for privileged, ambiguous, or destructive actions.

Idempotency

Scheduled jobs can run repeatedly without reapplying settled state or creating duplicate side effects.

Observability

Actions, failures, pending work, and cross-system inconsistencies are surfaced in useful operational summaries.

Usable security

Controls are embedded into tools employees and administrators can actually use, rather than added as separate friction.
